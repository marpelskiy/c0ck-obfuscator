## c0ck-obfuscator | Binary Encapsulation Engine

**Концепция:**
Система низкоуровневой инкапсуляции и динамической обфускации данных. Инструмент предназначен для предотвращения статического анализа файлов и обеспечения безопасности данных при их хранении и передаче. Основная задача — создание изолированной среды выполнения (in-memory execution), при которой данные существуют в открытом виде исключительно в оперативной памяти (RAM) процесса, не оставляя следов на энергонезависимых носителях.

### Ключевые архитектурные особенности:

* **Custom Containerization:** Использование проприетарного формата данных (`.c0ck`), исключающего распознавание содержимого стандартными средствами анализа (magic bytes validation).
* **Volatile Memory Processing:** Расшифровка потока данных выполняется непосредственно в стеке памяти движка, исключая запись промежуточных результатов на диск.
* **Environment Integrity Monitoring:** Интегрированные механизмы проверки окружения (anti-debugging), обеспечивающие мгновенное прекращение работы процесса при обнаружении попыток трассировки или динамического анализа (ptrace interception).
* **Zero-Footprint Payload:** Минимизация следов присутствия в системе за счет удаления отладочных символов при компиляции и очистки буферов памяти после выполнения задачи.

### Инструкция по эксплуатации (Operational Manual)

**1. Configuration (Настройка прав доступа):**
Перед инициализацией системы необходимо присвоить права на исполнение скрипту сборки:

```bash
chmod +x build.sh

```

**2. Build (Сборка архитектуры):**
Запустите процедуру компиляции для формирования исполняемого модуля `fortress_engine`:

```bash
./build.sh

```

*Система автоматически применит оптимизацию `-O3` и удалит отладочные символы (`-s`), обеспечивая минимальный размер и защиту от анализа.*

**3. Obfuscate :**
В процессе выполнения `build.sh` система запросит ввод целевого объекта. Укажите имя файла (например, `secret.txt`), который необходимо защитить. Инструмент произведет XOR-трансформацию и создаст контейнер `secret.c0ck`.

**4. Execute (Деобфускация и запуск):**
Для восстановления данных из контейнера `.c0ck` выполните команду:

```bash
./fortress_engine [название_файла.c0ck]

```

*Движок верифицирует сигнатуру заголовка, инициализирует анти-отладочные примитивы (`ptrace`) и восстанавливает бинарный поток в файл с префиксом `decrypted_`.*

**5. Sanitization (Протокол зачистки):**
Для соблюдения принципа «Zero-Footprint» (отсутствие следов) после завершения работы с восстановленными данными, необходимо выполнить принудительное удаление временных артефактов:

```bash
rm decrypted_*

```

*Данная команда удаляет все расшифрованные объекты, оставляя в директории только защищенные контейнеры и исходный код.*

**Пример типичного рабочего цикла:**

```bash
# 1. Подготовка
chmod +x build.sh

# 2. Сборка и упаковка
./build.sh
# (Ввод имени файла: data.txt)

# 3. Деобфускация
./fortress_engine data.c0ck

# 4. Зачистка
rm decrypted_data.txt

```
