## c0ck-obfuscator | Binary Encapsulation Engine

**Концепция:**
Система низкоуровневой инкапсуляции и динамической обфускации данных. Инструмент предназначен для предотвращения статического анализа файлов и обеспечения безопасности данных при их хранении и передаче. Основная задача — создание изолированной среды выполнения (in-memory execution), при которой данные существуют в открытом виде исключительно в оперативной памяти (RAM) процесса, не оставляя следов на энергонезависимых носителях.

### Ключевые архитектурные особенности:

* **Custom Containerization:** Использование проприетарного формата данных (`.c0ck`), исключающего распознавание содержимого стандартными средствами анализа (magic bytes validation).
* **Volatile Memory Processing:** Расшифровка потока данных выполняется непосредственно в стеке памяти движка, исключая запись промежуточных результатов на диск.
* **Environment Integrity Monitoring:** Интегрированные механизмы проверки окружения (anti-debugging), обеспечивающие мгновенное прекращение работы процесса при обнаружении попыток трассировки или динамического анализа (ptrace interception).
* **Zero-Footprint Payload:** Минимизация следов присутствия в системе за счет удаления отладочных символов при компиляции и очистки буферов памяти после выполнения задачи.

### Инструкция по эксплуатации(Operational Manual)

1. Build (Сборка):
Запустите build.sh. Скрипт проведет компиляцию исполняемого модуля fortress_engine с применением оптимизации -O3 и удалением отладочных символов (-s) для минимизации информативности бинарного файла при реверс-инжиниринге.

2. Obfuscate (Инкапсуляция):
При вызове скрипта укажите целевой объект. Исходные данные будут инкапсулированы в контейнер формата .c0ck с применением симметричного XOR-преобразования. Уникальная сигнатура заголовка (Magic Bytes) обеспечит валидацию контейнера.

3. Execute (Внутренняя деобфускация):
Запуск процесса осуществляется через fortress_engine <файл.c0ck>. Движок инициализирует анти-отладочные примитивы (ptrace), верифицирует целостность заголовка и выполняет деобфускацию байтового потока в оперативной памяти (RAM), исключая запись промежуточных состояний на физический носитель.

4. Revert/Extract (Извлечение данных):
Для восстановления исходного состояния объекта на диске (деобфускации):

    Используйте fortress_engine для вывода расшифрованного потока в файл (режим decrypted_).

    После завершения работы с восстановленным объектом, согласно протоколу Zero-Footprint, необходимо выполнить принудительную очистку (команда rm decrypted_*), чтобы исключить наличие открытых данных в энергонезависимой памяти.
